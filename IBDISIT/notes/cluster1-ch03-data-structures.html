3.1 Linear Data Structures: Arrays, Matrices & Linked Lists

Core Foundation

A. Array Memory Addressing (Row-Major vs. Column-Major)

Arrays store homogeneous elements in contiguous memory locations, enabling O(1) random access via base-address arithmetic. For a 2D array A[M][N] (M rows, N columns, element size w bytes, Base Address B, 0-based indices i, j):

  • Row-Major Order (C, C++, Java, Python): Addr(A[i][j]) = B + w × (i × N + j)
  • Column-Major Order (Fortran, MATLAB, R): Addr(A[i][j]) = B + w × (j × M + i)
  • General lower bounds [L1..U1][L2..U2]: Replace i with (i - L1), j with (j - L2), M = U1 - L1 + 1, N = U2 - L2 + 1.
  • Sparse Matrix: A matrix where most elements are zero. Stored compactly via 3-Tuple (Row, Col, Value) or CSR (Compressed Sparse Row) format to avoid wasting O(M × N) RAM.

B. Arrays vs. Singly / Doubly / Circular Linked Lists (Complexity Matrix)

Operation Static Array Singly Linked List (Head only) Doubly Linked List (Head + Tail) Circular LL (Tail pointer)
Random Access (k-th) O(1) O(n) O(n) O(n)
Insert / Delete at Head O(n) (shifting) O(1) O(1) O(1) (tail->next is head!)
Insert at Tail O(1) (if space) O(n) (O(1) with tail ptr) O(1) O(1)
Delete Last Node O(1) O(n) (even with tail ptr!) O(1) (has prev ptr) O(n)
Cache Locality Excellent (Spatial) Poor (pointer chasing) Poor (+ extra prev ptr RAM) Poor
Classic Linked List Exam Traps • Deleting the last node of a Singly Linked List takes O(n) even if a tail pointer is maintained, because you must find the second-last node to update its next to NULL!
• Floyd's Cycle Detection (Tortoise & Hare): Uses slow (+1 step) and fast (+2 steps) pointers to detect a loop in O(n) time and O(1) auxiliary space.

3.2 Stacks, Queues, Priority Queues & Expression Conversion

High MCQ & Trace Yield
Structure Discipline Core Operations & Conditions Key Applications
Stack LIFO (Last-In First-Out) push, pop, peek — all O(1).
Overflow: top == N-1; Underflow: top == -1.		 Function call stack / recursion, DFS, Undo/Redo, Backtracking, Infix→Postfix, Balanced parentheses.
Linear Queue FIFO (First-In First-Out) enqueue (rear), dequeue (front) — O(1).
Trap: suffers False Overflow when rear == N-1 even if front slots are free.		 CPU FCFS scheduling, print spoolers, BFS traversal, asynchronous messaging buffers.
Circular Queue FIFO (wrap-around) Full: (rear + 1) % N == front (sacrifices 1 slot, or tracks count). OS ring buffers, network NIC packet queues, Round-Robin scheduling.
Deque Insert/Delete at BOTH ends Input-restricted (insert 1 end) or Output-restricted (delete 1 end). Sliding Window Maximum (O(n)), Work-stealing thread schedulers.
Priority Queue Highest/Lowest priority out first Implemented via Binary Heap: Insert O(log n), Extract-Max/Min O(log n), Peek O(1). Dijkstra's shortest path, Prim's MST, Huffman coding, OS priority scheduling.

Infix, Prefix (Polish) & Postfix (Reverse Polish) Rules

  • Why Postfix/Prefix? Eliminates parentheses and operator precedence ambiguity; evaluated in a single left-to-right scan using one Stack (Prefix is evaluated right-to-left).
  • Operator Precedence & Associativity: 1. () → 2. ^ (Exponentiation — RIGHT-to-LEFT associative!) → 3. *, /, % (Left-to-Right) → 4. +, - (Left-to-Right).
  • Implementing Queue with 2 Stacks: Enqueue pushes to S1 (O(1)); Dequeue pops from S2 (if S2 is empty, transfer all from S1 → Amortized O(1)).

3.3 Trees: Binary Trees, BST, AVL, Red-Black Trees & Heaps

Top Paper III Objective Zone

A. Essential Binary Tree Identities (Memorize!)

  • Max nodes at level L (root at L=0): 2^L. Max nodes in tree of height h: 2^(h+1) - 1.
  • Min height of a binary tree with n nodes: floor(log2 n); Max height (skewed): n - 1.
  • Leaf vs. Degree-2 Node Theorem: In ANY non-empty binary tree, n_0 = n_2 + 1 (leaves = nodes with 2 children + 1).
  • Full (Strict) Binary Tree: Every node has 0 or 2 children. Total nodes = 2L - 1 (always odd).
  • Complete Binary Tree: All levels completely filled except possibly the last, which is filled left-to-right (used by Binary Heaps).
  • Catalan Number (Unlabeled Binary Trees / Distinct BSTs with n keys): C_n = (2n)! / [(n + 1)! · n!] (C_1=1, C_2=2, C_3=5, C_4=14, C_5=42).
  • Unique Tree Reconstruction: Inorder + Preorder OR Inorder + Postorder uniquely determines a binary tree. Preorder + Postorder alone is NOT unique (unless every internal node has 2 children, i.e., Full Binary Tree).

B. BST vs. AVL Tree vs. Red-Black Tree vs. Binary Heap

Tree Type Invariant / Balance Rule Search / Insert / Delete Key Exam Facts & Real-World Uses
BST Left < Root < Right;
Inorder traversal = Sorted order		 Avg: O(log n)
Worst (skewed): O(n)		 Deleting node with 2 children replaces it with Inorder Successor (min of right subtree) or Inorder Predecessor.
AVL Tree Balance Factor BF = H_L - H_R ∈ {-1, 0, +1} Worst: O(log n) guaranteed 4 rotations: LL (Right), RR (Left), LR (Left-Right), RL (Right-Left). Max 1 rotation (single/double) per insert; up to O(log n) per delete. Min nodes: N(h) = N(h-1) + N(h-2) + 1.
Red-Black Tree Root black; no two adjacent reds; equal black-height on all root-to-NULL paths Worst: O(log n) (Height ≤ 2 log2(n+1)) More loosely balanced than AVL → faster insertions/deletions (at most 2–3 rotations). Used in C++ std::map, Java TreeMap, Linux CFS scheduler.
Binary Heap Complete Binary Tree + Heap order (Max: parent ≥ children; Min: parent ≤ children) Peek: O(1) | Push/Pop: O(log n)
Build-Heap: O(n)		 Stored in 0-indexed array: parent = floor((i-1)/2), left = 2i+1, right = 2i+2. Last non-leaf node index = floor(n/2) - 1.

3.4 Graphs: Representations, BFS, DFS & Topological Sort

Metric / Operation Adjacency Matrix Adjacency List
Space Complexity O(V^2) O(V + E)
Check if Edge (u, v) Exists O(1) O(deg(u))
BFS / DFS Traversal Time O(V^2) O(V + E)
Best Suited For Dense graphs (E ≈ V^2) Sparse graphs (real-world networks, payment graphs)
  • BFS (Breadth-First Search): Uses a Queue. Guarantees the shortest path (minimum edges) in unweighted graphs, checks Bipartiteness (2-coloring), and finds level-order distances.
  • DFS (Depth-First Search): Uses a Stack / Recursion. Classifies edges into Tree, Back, Forward, and Cross edges (Back edge ↔ Cycle exists!). Powers Topological Sorting (only on DAGs), Strongly Connected Components (Kosaraju / Tarjan), and Articulation Points / Bridges.
  • Eulerian vs. Hamiltonian Trap: An undirected connected graph has an Eulerian Circuit iff every vertex has even degree (checkable in O(V+E)). Finding a Hamiltonian Cycle (visiting every vertex once) is NP-Complete.

3.5 Hashing, Collision Resolution & Dynamic Hashing

Frequent Paper III Trap

A Hash Table maps keys to bucket indices via a hash function h(k) (commonly Division Method h(k) = k mod m where m is a prime number not close to a power of 2), achieving O(1) average-case search/insert/delete (worst-case O(n) if all keys collide). Load factor α = n / m (keys / slots).

Collision Technique Probe Formula / Mechanism Load Factor α Clustering & Exam Traps
Separate Chaining (Open Hashing) Each bucket holds a linked list (or RB-tree in Java 8+ when length > 8) Can be > 1 No clustering; easy deletion; extra pointer memory & poorer cache locality.
Linear Probing (Open Addressing) (h(k) + i) mod m α ≤ 1 Best cache locality, but suffers severe Primary Clustering (long contiguous runs). Requires Tombstone (Deleted) markers on deletion!
Quadratic Probing (h(k) + c1·i + c2·i^2) mod m α ≤ 0.5 (for prime m) Eliminates primary clustering, but suffers Secondary Clustering (keys with same initial hash follow same probe path).
Double Hashing (h1(k) + i · h2(k)) mod m α ≤ 1 Eliminates BOTH primary & secondary clustering. Rule: h2(k) must NEVER evaluate to 0 and should be coprime to m.
  • Dynamic Hashing (for growing database files): Extendible Hashing uses a memory directory of size 2^D (Global Depth D) pointing to disk buckets (Local Depth d); splits only the overflowing bucket (doubles directory only when d == D)—no overflow chains! Linear Hashing splits buckets sequentially round-robin without a directory.

3.6 File Structures, Indexing, B-Trees & B+ Trees

Critical DBMS + File Structures Bridge

A. File Organization & Index Types

Index / File Type Ordering on Data File Dense or Sparse? Key Exam Property
Primary Index Ordered on Key field Sparse (1 entry per disk block — anchor record) At most 1 primary index per table; binary search on index = ceil(log2 b_i) + 1 disk I/Os.
Clustering Index Ordered on Non-Key field (duplicates allowed) Sparse (1 entry per distinct field value) Great for grouping records by branch_id or msme_sector.
Secondary Index Data file is Unordered on this field ALWAYS Dense (1 entry per record!) A table can have multiple secondary indexes (e.g., PAN, Udyam ID, mobile).
ISAM (Indexed Sequential) Static sequential blocks + static index Multi-level static sparse Degrades over time as inserts create overflow chains (solved by B+ Trees!).

B. B-Tree vs. B+ Tree Architecture (Why Banks & RDBMS Use B+ Trees)

Feature (Order p) B-Tree B+ Tree
Data / Record Pointers Stored in BOTH internal and leaf nodes Stored ONLY in leaf nodes (internal nodes store routing keys only)
Duplicate Keys No key is repeated Internal routing keys are duplicated in leaf nodes
Fan-out & Height Lower fan-out (record pointers consume block space) Higher fan-out → shorter height → fewer disk reads
Range / Sequential Queries Slow (requires repeated tree traversal) Very fast (leaves form a sorted doubly/singly linked list)
Block Size Order Formula p·P_b + (p-1)·(K + P_r) ≤ B Internal: p·P_b + (p-1)·K ≤ B
Leaf: p_leaf·(K + P_r) + P_b ≤ B
Min Children (Non-Root) ceil(p / 2) children, ceil(p / 2) - 1 keys ceil(p / 2) children, ceil(p / 2) - 1 keys (all leaves at same depth!)

3.7 Worked Exam Numericals (7 Step-by-Step Problems)

2-Mark Paper III Favorites
Numerical 1: 2D Array Row-Major vs. Column-Major Address Problem: Array A[10][20] (0-based), Base B = 1000, element size w = 4 bytes. Find address of A[3][5] in Row-Major and Column-Major.
Row-Major: 1000 + 4 × (3 × 20 + 5) = 1000 + 4 × 65 = 1260.
Column-Major: 1000 + 4 × (5 × 10 + 3) = 1000 + 4 × 53 = 1212.
Numerical 2: Infix to Postfix Conversion & Postfix Evaluation (a) Convert Infix A + B * (C ^ D - E) to Postfix:
Scan: A → push + → B → push * → push ( → C → push ^ → D → - pops ^ → E → ) pops - → end pops *, + → A B C D ^ E - * +.
(b) Evaluate Postfix 6 2 3 + - 3 8 2 / + *:
2+3=5 → 6-5=1 (Stack: [1]) → 8/2=4 → 3+4=7 (Stack: [1, 7]) → 1*7 = 7.
Numerical 3: Tree Reconstruction & Catalan Count Problem: Given Preorder = A B D E C F and Inorder = D B E A F C, find Postorder. Also find distinct BSTs for n = 4 keys.
Step 1: First of Preorder is Root = A. In Inorder, {D,B,E} is Left subtree, {F,C} is Right subtree.
Step 2: Left root = B (left D, right E). Right root = C (left F).
Postorder (L-R-N): D E B F C A.
Catalan (n=4): C_4 = 8! / (5! · 4!) = 40320 / (120 × 24) = 14 distinct BSTs.
Numerical 4: AVL Tree Insertion & LR Rotation Trace Problem: Insert 30, 10, 20 sequentially into an empty AVL Tree.
Trace: Insert 30 (root) → Insert 10 (left of 30) → Insert 20 (right of 10).
Now at 30, BF = 2 - 0 = +2; at left child 10, BF = 0 - 1 = -1 → LR Imbalance!
Fix: (1) Left-rotate around 10 (20 becomes left child of 30, 10 left of 20); (2) Right-rotate around 30 → New balanced root = 20 (Left: 10, Right: 30).
Numerical 5: Double Hashing Probe Sequence Problem: Hash table size m = 11, h1(k) = k mod 11, h2(k) = 7 - (k mod 7). Insert keys 22, 33.
Trace: 22 → h1(22) = 0 (placed at slot 0).
33 → h1(33) = 0 (collision!). Compute h2(33) = 7 - (33 mod 7) = 7 - 5 = 2.
Probe i = 1: (0 + 1 × 2) mod 11 = slot 2.
Numerical 6: B+ Tree Internal Node Order Calculation (Classic GATE/SIDBI) Problem: Disk block size B = 4096 B, Search Key K = 12 B, Block Pointer P_b = 8 B, Record Pointer P_r = 10 B. Find the maximum order p of an internal node of a B+ Tree.
Formula (Internal node has NO record pointers!): p · P_b + (p - 1) · K ≤ B
p(8) + (p - 1)(12) ≤ 4096 → 20p - 12 ≤ 4096 → 20p ≤ 4108 → p ≤ 205.4 → p = 205.
Numerical 7: Primary Index Binary Search Disk I/O Problem: A sorted loan file has 30,000 records (100 B each) on 1024 B blocks (unspanned). Primary index entry is 15 B. Find worst-case disk accesses with vs. without the primary index.
Data Blocks: Blocking factor bfr = floor(1024 / 100) = 10 records/block → 30000 / 10 = 3000 data blocks. Binary search without index = ceil(log2 3000) = 12 I/Os.
Index Blocks: Primary index is sparse → 3000 index entries. bfr_i = floor(1024 / 15) = 68 → ceil(3000 / 68) = 45 index blocks.
With Primary Index = ceil(log2 45) + 1 = 6 + 1 = 7 I/Os (42% reduction in disk reads!).

3.8 Banking & SIDBI Data-Engine Context + 10-Mark Descriptive Blueprint

Descriptive Edge
  • B+ Trees in Core Banking RDBMS (Oracle / PostgreSQL / InnoDB): Every MSME loan ledger query filtering by date range (WHERE disbursal_date BETWEEN '2026-04-01' AND '2026-09-30') or sorted statement pagination relies on B+ Tree linked leaf chains for O(log_p N + k) I/O efficiency.
  • Hash Indexes & Bloom Filters in Real-Time Payments: Exact-match lookups (verifying an IFSC code, Udyam Registration Number, or checking a PAN against a sanctions/AML watchlist) use Hash Tables and probabilistic Bloom Filters (zero false negatives, tiny RAM footprint) before hitting disk.
  • Graphs in Fraud & Supply-Chain Finance: Detecting circular invoice discounting or shell-company collusion on platforms like TReDS (RXIL) and GST Sahay models buyers, sellers, and financiers as directed weighted graphs using DFS cycle detection and connected components.
Paper III (Part B) 10-Mark Descriptive Model Blueprint Probable Question: "Why do enterprise banking RDBMS storage engines prefer B+ Trees over Binary Search Trees, Hash Indexes, and standard B-Trees for indexing loan and transaction tables?" (10 Marks | 200 Words)
• Intro (25w): Disk I/O is orders of magnitude slower than RAM; database indexes optimize block reads, not just CPU comparisons.
• Why not BST / AVL (45w): Binary trees have fan-out 2 → depth ~20+ for 1M accounts (20 random disk seeks); B+ Trees pack hundreds of keys per 4KB/8KB page → height 3–4.
• Why B+ Tree beats B-Tree & Hashing (105w): (1) Internal nodes omit record pointers → higher fan-out; (2) Linked leaf pointers enable instant SQL BETWEEN / ORDER BY range scans (Hash indexes fail on range queries!); (3) Predictable uniform leaf depth.
• Conclusion (25w): Pair B+ Trees (primary/range ledger queries) with Hash Indexes (exact-match ID/KYC lookups) for hybrid banking performance.

3.9 5-Minute Rapid Revision Sheet & 15 Exam-Level Practice MCQs

Last-Day Cram + Drill
  1. Row-Major (C/Java): B + w(i·N + j); Column-Major (Fortran/MATLAB): B + w(j·M + i).
  2. Deleting the last node of a Singly LL is O(n) even with a tail pointer; Doubly LL does it in O(1).
  3. Floyd's Cycle Detection (slow/fast pointers) runs in O(n) time and O(1) space.
  4. Circular Queue full condition: (rear + 1) % N == front.
  5. Exponentiation (^) is Right-to-Left associative; all basic arithmetic ops (+ - * /) are Left-to-Right.
  6. Queue using 2 Stacks achieves Amortized O(1) per operation.
  7. In any non-empty binary tree: Leaves (n_0) = Degree-2 nodes (n_2) + 1.
  8. Distinct BSTs with n keys = Catalan Number C_n = (2n)! / ((n+1)!n!) (n=3→5, n=4→14).
  9. Inorder traversal of a BST always produces keys in strictly ascending sorted order.
  10. Unique binary tree reconstruction needs Inorder + Preorder OR Inorder + Postorder.
  11. AVL Tree Balance Factor BF ∈ {-1, 0, +1}; min nodes N(h) = N(h-1) + N(h-2) + 1.
  12. Red-Black Trees do fewer rotations on insert/delete than AVL (used in C++ std::map, Java TreeMap).
  13. Build-Heap takes O(n) time (NOT O(n log n)!); Insert/Extract takes O(log n).
  14. BFS uses a Queue (unweighted shortest path); DFS uses a Stack (back-edge = cycle, Topological Sort on DAGs).
  15. Adjacency Matrix = O(V^2) space, O(1) edge check; Adjacency List = O(V+E) space (best for sparse graphs).
  16. Eulerian circuit exists iff connected & all vertices have even degree; Hamiltonian cycle is NP-Complete.
  17. Linear Probing → Primary Clustering; Quadratic Probing → Secondary Clustering; Double Hashing → eliminates both!
  18. Open Addressing deletions require Tombstone (Deleted) markers so probe chains aren't broken.
  19. Extendible Hashing uses Global Depth D & Local Depth d with zero overflow chains.
  20. Primary & Clustering Indexes are Sparse; Secondary Index (on unordered field) is ALWAYS Dense.
  21. B+ Tree stores record pointers ONLY in leaves; internal nodes store keys + block pointers only (higher fan-out!).
  22. B+ Tree leaves are linked sequentially, making SQL range queries (BETWEEN) ultra-fast.
  23. B+ Tree internal order formula: p·P_b + (p-1)·K ≤ B.
  24. Hash Indexes excel at exact equality (=) but cannot efficiently serve range queries (<, >, BETWEEN).
  25. Bloom Filter guarantees 0% false negatives (may have small false-positive rate) in minimal RAM.
