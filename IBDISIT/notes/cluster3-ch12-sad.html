Chapter 12: Systems Analysis & Design (SAD)

Complete exam-depth treatise on Systems Theory, TELOS Feasibility & NPV/ROI/Payback math, JAD/RAD/Requirements elicitation, DFD rules & Context Diagram (SVG), Data Dictionary & Decision Tables, Cohesion & Coupling spectra, System Conversion strategies (Direct/Parallel/Pilot/Phased), 6 worked SAD problems, SIDBI/RBI banking implementation context, 25 one-liners, and 15 exam-level 5-option MCQs.

12.1 Systems Concepts, Classifications & Role of Systems Analyst

Core Foundation
  • Five Characteristics of a System: Organization, Interaction, Interdependence, Integration, and Central Objective.
  • System Classifications: • Open vs. Closed System: An Open System exchanges inputs, outputs, and feedback with its external environment (e.g., Core Banking interacting with RBI/NPCI/MSMEs); a Closed System is isolated from its environment (theoretical in business IT).
    • Feedback Control: Negative Feedback corrects deviations to maintain stability/equilibrium (e.g., auto-scaling servers when CPU > 80%); Positive Feedback amplifies change.
    • Deterministic vs. Probabilistic: Deterministic produces exact predictable output for given input (EMI formula); Probabilistic has statistical uncertainty (NPA credit-default forecast).
  • Role of a Systems Analyst: Acts as a change agent bridging business stakeholders and software engineers—produces BRD (Business Requirements Document — "Why & What"), FRD / SRS (Functional / Software Requirements Spec), and vendor RFP (Request for Proposal).

  • Economic Feasibility Formulas: • Payback Period: Time required for cumulative net cash inflows to recover initial investment.
    • ROI (%): [(Total Benefits - Total Costs) / Total Costs] × 100.
    • Net Present Value (NPV): NPV = Σ [CF_t / (1 + r)^t] - Initial_Cost (accounts for Time Value of Money; accept project iff NPV > 0!).

Functional vs. Non-Functional Requirements (NFRs): Functional requirements specify WHAT the system must do (e.g., "Calculate GST-linked credit limit"); NFRs specify HOW WELL it must perform (e.g., "99.95% uptime, <300 ms API p95 latency, AES-256 encryption, RBAC audit logs").

12.4 Structured Analysis: DFDs (SVG), Data Dictionary & Decision Tables

Top SAD Objective Trap Zone
  • 4 DFD Symbols: External Entity (Rectangle), Process (Circle / Rounded Rectangle), Data Store (Open-ended Rectangle / Parallel Lines), Data Flow (Labeled Arrow). Trap: DFDs show logical data movement, NOT control flow or loops (unlike Flowcharts!).
  • DFD Validation Traps: • Context Diagram (Level 0): Always has exactly ONE Process ("0") and NO Data Stores.
    • Balancing: External inputs/outputs entering Level-0 MUST exactly match Level-1.
    • Black Hole: Process with inputs only, ZERO outputs (error!). Miracle: Process with outputs only, ZERO inputs (error!). Gray Hole: Inputs insufficient to produce outputs.
  • Data Dictionary Notation: = (is composed of), + (AND), [A | B] (either A or B), {X} (iteration / 0 or more), (Y) (optional).
  • Decision Tables vs. Decision Trees: A Decision Table has 4 quadrants (Condition Stub, Condition Entry, Action Stub, Action Entry) and handles complex multi-condition business rules exhaustively (2^n rules for n binary conditions); a Decision Tree is better for sequential branching rules.

12.5 Structured Design: Structure Charts, Cohesion & Coupling Spectra

Guaranteed 1–2 Mark MCQ

Good modular design maximizes Cohesion (intra-module unity) and minimizes Coupling (inter-module dependency).

Rank Cohesion (BEST → WORST: F-S-C-P-T-L-C) Coupling (BEST → WORST: D-S-C-E-C-C)
1 (BEST)Functional: All elements perform ONE single well-defined taskData: Modules pass only needed primitive/atomic data parameters
2Sequential: Output of one element is input to the next (pipeline)Stamp: Modules pass an entire composite struct/object when only 1 field is needed
3Communicational: Elements operate on the same input/output data setControl: One module passes a control flag telling another WHAT branch to run
4Procedural: Elements grouped because they follow a sequence of stepsExternal: Modules share an external data format, protocol, or device interface
5Temporal: Elements grouped only because they run at the same time (e.g., startup/init)Common: Modules read/write the same global shared data area
6Logical: Loosely related tasks selected via a control flag (e.g., all I/O routines)Content (WORST): One module directly modifies internal code/local data of another!
7 (WORST)Coincidental: Unrelated tasks dumped arbitrarily into one module—

12.6 Input Validation Controls & System Conversion (Cutover) Strategies

Banking Implementation Core
  • Input Validation Controls: Presence check (mandatory field), Format/Mask check (PAN [A-Z]{5}[0-9]{4}[A-Z]), Range check, Check-Digit (Luhn algorithm for credit cards; Verhoeff algorithm for Aadhaar), and Batch Control Totals (Record Count + Hash Total).
Conversion Strategy Mechanism Risk Cost Banking Suitability
1. Direct Cutover (Plunge) Old system shut down; new system goes live immediately HIGHEST Lowest Non-critical internal tools ONLY (too risky for CBS!)
2. Parallel Operation Both old & new run simultaneously on live data; outputs reconciled LOWEST (Safest) Highest (2× ops) Gold standard for Core Banking / Loan Ledger migrations
3. Pilot Conversion Deploy full new system at 1–2 test branches first, then roll out nationally Low–Moderate Moderate Ideal for multi-branch Regional Office portal rollouts
4. Phased (Staged) Roll out module-by-module over time (e.g., Origination → Disbursal → NPA) Low–Moderate Moderate Large enterprise modernization (Strangler Fig pattern)

12.7 Worked Exam Numericals & SAD Modeling Problems (6 Cases)

Step-by-Step Solutions
Problem 1: Economic Feasibility — Payback Period, ROI & NPV Given: An MSME automation portal costs ₹40 Lakh upfront and generates net annual savings of ₹20 Lakh for 3 years. Discount rate r = 10%.
• Payback Period: 40 / 20 = 2.0 years.
• Simple ROI: [(60 - 40) / 40] × 100 = 50%.
• NPV: 20/1.1 + 20/1.21 + 20/1.331 - 40 = 18.18 + 16.53 + 15.03 - 40 = +₹9.74 Lakh (> 0 ⇒ Economically Feasible!).
Problem 2: Decision Table Exhaustive Rule Count Problem: A loan auto-approval engine checks 4 binary (Y/N) conditions: Udyam Valid?, CIBIL ≥ 700?, GST Active?, Not on Watchlist? How many rules are in a complete Limited-Entry Decision Table?
Formula: 2^n = 2^4 = 16 rules.
Problem 3: Spot the Illegal DFD Errors Diagram shows: (a) Customer → Loan_DB directly; (b) Process 2.1 Validate KYC receives 2 inputs and produces 0 outputs; (c) Process 2.2 Generate OTP has 0 inputs and outputs OTP.
Errors: (a) Illegal Entity-to-Data-Store direct flow; (b) Black Hole; (c) Miracle.
Problem 4: Identifying Coupling Type Module CalculateEMI() receives the entire 40-field CustomerProfile struct even though it only reads credit_score. What coupling is this?
Answer: Stamp Coupling (passing an entire composite record when only a subset is needed; refactor to Data Coupling by passing only credit_score!).
Problem 5: Data Dictionary Notation Parsing MSME_Loan = Loan_ID + PAN + (CoApplicant_PAN) + [Term_Loan | Working_Cap] + {EMI_Row}
Meaning: Mandatory Loan_ID & PAN, optional CoApplicant_PAN, either Term Loan OR Working Capital, and zero or more repeating EMI_Row entries.
Problem 6: Choosing Cutover Strategy for Core Banking vs. Regional Portal • Replacing a live Core Banking interest ledger where zero balance error is mandatory → Parallel Operation.
• Rolling out a new branch-level MSME onboarding UI across 100 offices → Pilot Conversion (2 branches first).

12.8 Banking & SIDBI Systems Analysis Context + 10-Mark Blueprint

Descriptive Edge

When AIFIs like SIDBI procure or modernize platforms such as the SIDBI–RRB Co-Lending Origination Platform or Udyamimitra, structured SAD discipline—TELOS feasibility, JAD workshops with partner banks, formal BRD/SRS sign-off, UAT, Parallel Runs, and Post-Implementation Reviews—is mandated under RBI's Master Direction on IT Governance.

Paper III (Part B) 10-Mark Descriptive Model Blueprint Probable Question: "Compare Direct, Parallel, Pilot, and Phased system conversion strategies. Recommend an optimal migration plan for modernizing a legacy MSME Loan Management System at SIDBI." (10 Marks | 200 Words)
• Intro (25w): Cutover is the highest-risk phase of enterprise IT modernization where financial continuity is on the line.
• 4-Strategy Comparison (85w): Contrast Direct (cheapest, catastrophic rollback risk), Parallel (safest reconciliation, 2× operational load), Pilot (branch-scoped validation), and Phased (modular incremental rollout).
• Recommended Hybrid Plan (70w): Adopt a Phased + Pilot + Parallel strategy—migrate read-only reporting and origination modules first via a 2-branch Pilot, and run a strict 30-day Parallel reconciliation for disbursement/interest posting before legacy decommissioning.
• Conclusion (20w): Pair with automated data-migration checksums and Board IT committee sign-off.

12.9 5-Minute Rapid Revision Sheet & 15 Exam-Level Practice MCQs

Last-Day Cram + Drill
  1. Open System interacts with its environment via feedback; Negative Feedback maintains stability.
  2. TELOS Feasibility: Technical, Economic, Legal, Operational, Schedule.
  3. PIECES Framework: Performance, Information, Economics, Control, Efficiency, Service.
  4. NPV > 0 means project is economically viable after accounting for Time Value of Money.
  5. JAD (Joint Application Design) uses facilitated group workshops to align users & analysts rapidly.
  6. Hawthorne Effect: Users alter normal behavior when they know they are being observed.
  7. DFDs model logical data flow, NOT control logic or loops.
  8. Level-0 Context DFD has exactly ONE process ("0") and ZERO Data Stores.
  9. Illegal DFD flows: Entity→Entity, Entity→Store, Store→Store (a Process MUST mediate!).
  10. Black Hole = process with inputs only; Miracle = process with outputs only.
  11. DFD Balancing: Level-0 inputs/outputs must strictly match Level-1 child DFD.
  12. Data Dictionary: + AND, () Optional, {} Repeating, [|] Either/Or.
  13. Complete Limited-Entry Decision Table with n binary conditions has 2^n rules.
  14. Best Cohesion = Functional; Worst Cohesion = Coincidental (F-S-C-P-T-L-C).
  15. Best Coupling = Data; Worst Coupling = Content (D-S-C-E-C-C).
  16. Stamp Coupling passes an entire composite struct when only 1 field is needed.
  17. Common Coupling shares global mutable state across modules.
  18. High Fan-In = good module reuse; Low/Moderate Fan-Out = clean span of control.
  19. Structure Chart open-circle arrow = Data Couple; filled-circle arrow = Control Flag.
  20. Luhn algorithm validates card check digits; Verhoeff algorithm validates Aadhaar check digits.
  21. Direct Cutover = lowest cost, HIGHEST risk (avoid for CBS!).
  22. Parallel Operation = SAFEST (reconciles old vs. new), highest operational cost.
  23. Pilot Conversion tests the entire system at 1–2 branches before wide rollout.
  24. Phased Conversion deploys one functional module at a time.
  25. BRD captures business goals ("Why/What"); SRS/FRD defines verifiable technical & functional specs.
