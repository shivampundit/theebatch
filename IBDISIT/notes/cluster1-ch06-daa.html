6.1 Asymptotic Analysis, Growth Hierarchy & Master Theorem

Guaranteed MCQ Zone
  • Asymptotic Bounds: O(g(n)) (Big-O) = asymptotic upper bound (≤); Ω(g(n)) (Big-Omega) = asymptotic lower bound (≥); Θ(g(n)) (Big-Theta) = tight bound (both O and Ω); o(g(n)) / ω(g(n)) = strictly smaller / strictly larger (non-tight).
  • Strict Growth Rate Order (Fastest → Slowest): O(1) < O(log log n) < O(log n) < O(√n) < O(n) < O(n log n) < O(n^2) < O(n^3) < O(2^n) < O(n!) < O(n^n).

Master Theorem: T(n) = a · T(n / b) + f(n) (where a ≥ 1, b > 1)

Compute critical polynomial n^c where c = log_b(a), and compare with f(n):

Case Condition Comparing f(n) vs. n^(log_b a) Asymptotic Solution T(n) Classic Example
Case 1
(Leaves dominate)		 f(n) = O(n^(c - ε)) for some ε > 0 Θ(n^(log_b a)) T(n)=4T(n/2)+n → c=2 > 1 → Θ(n^2)
Case 2
(Balanced)		 f(n) = Θ(n^c · log^k n) for k ≥ 0 Θ(n^c · log^(k+1) n) Merge Sort: 2T(n/2)+n (k=0) → Θ(n log n)
2T(n/2)+n log n (k=1) → Θ(n log^2 n)
Case 3
(Root dominates)		 f(n) = Ω(n^(c + ε)) AND regularity a·f(n/b) ≤ d·f(n) (d<1) Θ(f(n)) T(n)=2T(n/2)+n^2 → c=1 < 2 → Θ(n^2)

Decrease-and-Conquer Recurrences (Master Theorem does NOT apply!): T(n)=T(n-1)+1 → Θ(n) • T(n)=T(n-1)+n → Θ(n^2) • T(n)=2T(n-1)+1 → Θ(2^n) (Tower of Hanoi) • T(n)=T(n-1)+T(n-2)+1 → O(2^n) (Naive Fibonacci).

6.2 Divide & Conquer + Complete Sorting & Searching Matrix

Top Objective Yield

Comparison-Sort Lower Bound: Any deterministic comparison-based sorting algorithm requires at least Ω(n log n) comparisons in the worst case (decision tree has n! leaves → height ≥ log2(n!) = Θ(n log n)).

Algorithm Best Average Worst Aux Space Stable? In-Place?
Bubble Sort (opt) O(n) O(n^2) O(n^2) O(1) Yes Yes
Insertion Sort O(n) (nearly sorted!) O(n^2) O(n^2) O(1) Yes Yes
Selection Sort O(n^2) O(n^2) O(n^2) O(1) No Yes (min O(n) swaps!)
Merge Sort O(n log n) O(n log n) O(n log n) O(n) Yes No
Quick Sort O(n log n) O(n log n) O(n^2) (sorted + bad pivot) O(log n) stack No Yes
Heap Sort O(n log n) O(n log n) O(n log n) O(1) No Yes
Counting Sort O(n + k) O(n + k) O(n + k) O(n + k) Yes No (Non-comparison)
Radix Sort O(d(n+k)) O(d(n+k)) O(d(n+k)) O(n + k) Yes No (needs stable sub-sort!)
  • Key Divide & Conquer Milestones: Strassen's Matrix Multiplication reduces 8 sub-multiplications to 7 → T(n) = 7T(n/2) + O(n^2) = O(n^2.81); Karatsuba Multiplication = O(n^1.585); QuickSelect finds k-th smallest in O(n) expected time; TimSort (Python & Java Arrays.sort for objects) = Hybrid Merge + Insertion Sort (stable, O(n log n)).

6.3 Greedy Algorithms & Minimum Spanning Trees (MST)

A problem admits a Greedy solution iff it satisfies two properties: (1) Optimal Substructure and (2) Greedy Choice Property (a locally optimal choice leads to a globally optimal solution without reconsidering past choices).

Greedy Problem Greedy Criterion Time Complexity Exam Traps
Activity Selection Sort by Earliest Finish Time O(n log n) Sorting by start time or shortest duration FAILS!
Fractional Knapsack Sort by Value / Weight ratio desc O(n log n) Works ONLY when items can be split; FAILS for 0/1 Knapsack.
Huffman Coding Repeatedly merge two lowest-frequency nodes (Min-Heap) O(n log n) Produces optimal prefix-free variable-length binary code.
Kruskal's MST Sort ALL edges by weight; add if no cycle (Disjoint Set Union) O(E log E) Best for Sparse graphs; works on disconnected graphs (produces MSF).
Prim's MST Grow single tree from vertex by adding min-weight cut edge (Min-Heap) O((V+E) log V) (Heap)
O(V^2) (Matrix)		 Best for Dense graphs. Rule: If all edge weights are distinct, MST is UNIQUE!

6.4 Dynamic Programming (DP) — Top-Down vs. Bottom-Up & Classic Matrix

High Paper III Yield

Dynamic Programming applies when a problem exhibits Optimal Substructure AND Overlapping Subproblems (unlike Divide & Conquer where subproblems are independent/disjoint). Implemented via Top-Down Memoization (recursion + cache) or Bottom-Up Tabulation (iterative table).

Classic DP Problem Core Recurrence / State Time Complexity Key Exam Nuance
0/1 Knapsack dp[i][w] = max(dp[i-1][w], v_i + dp[i-1][w-w_i]) O(n · W) Pseudo-polynomial (exponential in bit-length of W); decision version is NP-Complete.
Matrix Chain Mult. (MCM) m[i][j] = min_k(m[i][k] + m[k+1][j] + p_{i-1}p_k p_j) O(n^3) (Space O(n^2)) Number of parenthesizations for n matrices = Catalan C_(n-1).
LCS (Longest Common Subseq) Match: 1 + dp[i-1][j-1]; else max(up, left) O(m · n) Subsequence need NOT be contiguous (unlike Substring).
LIS (Longest Increasing Subseq) dp[i] = 1 + max(dp[j]) for a[j] < a[i] O(n^2) DP / O(n log n) Binary Search Patience sorting maintains smallest tail of each length.
Edit Distance (Levenshtein) Min Insert / Delete / Replace cost O(m · n) Core algorithm for fuzzy KYC/AML sanction-list name matching!

6.5 Graph Shortest Paths & Network Max-Flow

Algorithm Scope Paradigm Handles Negative Edges? Time Complexity
BFS Single-Source (Unweighted) Queue traversal N/A (all weights = 1) O(V + E)
Dijkstra Single-Source Greedy (Min-Heap) NO (can fail!) O((V + E) log V)
Bellman-Ford Single-Source DP (V-1 relaxations) YES + detects negative cycles (on V-th pass) O(V · E)
Floyd-Warshall All-Pairs DP YES (neg cycle iff dist[i][i] < 0) O(V^3)
DAG Shortest Path Single-Source (DAG) Topological Sort YES (no cycles exist!) O(V + E)

Network Flow: By the Max-Flow Min-Cut Theorem, maximum flow from Source S to Sink T equals minimum capacity of an S-T cut. Ford-Fulkerson takes O(E · f*); Edmonds-Karp (BFS shortest augmenting path) guarantees polynomial O(V · E^2).

6.6 String Matching, Backtracking & Branch-and-Bound

String Algorithm Preprocessing Matching Time Core Mechanism (Text n, Pattern m)
Naive O(1) O((n - m + 1) · m) Shifts pattern by 1 on every mismatch.
KMP (Knuth-Morris-Pratt) O(m) (LPS / π table) O(n + m) worst-case Never moves text pointer backward; uses longest proper prefix = suffix.
Rabin-Karp O(m) Avg: O(n + m); Worst: O(nm) Rolling Hash (great for multi-pattern / plagiarism detection; spurious hits verified char-by-char).
  • Backtracking vs. Branch-and-Bound: Both explore a state-space tree with pruning. Backtracking uses DFS for feasibility/decision problems (N-Queens, Sudoku, Graph Coloring, Subset Sum). Branch-and-Bound uses BFS / Least-Cost (Best-First) Search with a numeric cost bound for optimization problems (TSP, 0/1 Knapsack).

6.7 Complexity Classes: P, NP, NP-Complete & NP-Hard

High-Yield Theory Trap
  • P: Decision problems solvable in deterministic polynomial time (O(n^k)).
  • NP: Decision problems whose "YES" certificate can be verified in polynomial time (equivalently, solvable by a Non-Deterministic Turing Machine in poly time). Trap: NP means Non-Deterministic Polynomial, NOT "Non-Polynomial"!
  • NP-Hard: Problem H such that every problem L ∈ NP reduces to H in polynomial time (L ≤_p H). An NP-Hard problem does NOT have to be in NP (e.g., Halting Problem, TSP Optimization).
  • NP-Complete (NPC): Hardest problems in NP (NP ∩ NP-Hard). By the Cook–Levin Theorem, Boolean Satisfiability (SAT) was the first proven NP-Complete problem. If ANY single NPC problem is solved in polynomial time, then P = NP!

6.8 Worked Exam Numericals (7 Step-by-Step Problems)

2-Mark Scoring Zone
Numerical 1: Master Theorem 3-Case Drill (a) T(n) = 4T(n/2) + n → n^(log_2 4) = n^2 > n (Case 1) → Θ(n^2).
(b) T(n) = 2T(n/2) + n log n → n^(log_2 2) = n, k = 1 (Case 2) → Θ(n log^2 n).
(c) T(n) = 2T(n/2) + n^2 → n^2 > n^1 (Case 3) → Θ(n^2).
Numerical 2: Why Greedy Fails on 0/1 Knapsack Capacity W = 50. Items: A(w=10, v=60, ratio=6), B(w=20, v=100, ratio=5), C(w=30, v=120, ratio=4).
• Greedy (by ratio): Picks A + B (weight 30, value 160; C doesn't fit!) → 160 (Suboptimal!).
• DP (Optimal 0/1): Picks B + C (weight 50) → 220. (Fractional Knapsack picks A + B + 2/3 C = 240).
Numerical 3: Huffman Coding Average Bits per Symbol Frequencies: A: 0.45, B: 0.25, C: 0.20, D: 0.10.
Merge D(0.10)+C(0.20)=0.30 → merge B(0.25)+0.30=0.55 → merge A(0.45)+0.55=1.00.
Code lengths: A=1 bit, B=2 bits, C=3 bits, D=3 bits.
Avg Length: 0.45(1) + 0.25(2) + 0.20(3) + 0.10(3) = 0.45 + 0.50 + 0.60 + 0.30 = 1.85 bits/symbol (vs. 2.00 fixed-length).
Numerical 4: Matrix Chain Multiplication (MCM) Matrices: A(10×30), B(30×5), C(5×60).
• (AB)C: (10×30×5) + (10×5×60) = 1500 + 3000 = 4,500 multiplications.
• A(BC): (30×5×60) + (10×30×60) = 9000 + 18000 = 27,000 (6× slower!).
Numerical 5: Dijkstra's Negative-Edge Failure Counterexample Graph: S → A (weight 5), S → B (weight 2), A → B (weight -10).
Dijkstra greedily locks B first with distance 2, missing the shorter path S → A → B = 5 + (-10) = -5! Use Bellman-Ford instead.
Numerical 6: KMP Prefix Function (LPS Table) Pattern: P = "A B A B A C A" (0-indexed).
LPS = [0, 0, 1, 2, 3, 0, 1] (at index 4, "ABABA" has longest proper prefix = suffix "ABA" of length 3).
Numerical 7: Maximum Edges & MST Weight Check A connected undirected graph has V = 12 vertices and E = 30 edges. Any Minimum Spanning Tree (MST) MUST contain exactly V - 1 = 11 edges, and removing any single edge disconnects the MST into 2 components.

6.9 Banking Algorithmic Context, 25 One-Liners & 15 Exam MCQs

Descriptive + Cram + Drill
Banking & SIDBI Real-World Algorithm Applications (10-Mark Descriptive Hooks)
  • AML / KYC Fuzzy Name Screening: Uses Levenshtein Edit Distance (DP) and phonetic algorithms to catch spelling variations against UN/OFAC/RBI sanction lists.
  • RTGS / Interbank Liquidity Netting: Models queued interbank payment obligations as directed graphs to detect multilateral netting cycles and resolve liquidity gridlocks via Max-Flow / Cycle-Canceling algorithms.
  • MSME Capital & Refinance Allocation: Optimizing limited subsidy or green-finance corpus across competing MSME proposals maps to 0/1 Knapsack / Linear Programming.
  • TLS & Digital Signatures Security: Modern banking encryption (RSA/ECC protecting SIDBI Digital Portals) relies on the computational intractability of integer factorization / discrete logarithm problems (believed outside P).

5-Minute Rapid Revision Sheet (25 High-Yield One-Liners)

  1. Growth order: 1 < log log n < log n < √n < n < n log n < n^2 < 2^n < n! < n^n.
  2. Master Theorem compares f(n) against n^(log_b a); Case 2 multiplies by an extra log n.
  3. T(n) = 2T(n-1) + 1 (Tower of Hanoi) solves to Θ(2^n) (Master Theorem does NOT apply!).
  4. Comparison-based sorting lower bound = Ω(n log n) via decision tree of n! leaves.
  5. Insertion Sort runs in O(n) on nearly sorted inputs; Selection Sort minimizes total swaps (O(n)).
  6. Merge Sort = O(n log n) worst, Stable, NOT in-place (O(n) space).
  7. Quick Sort = O(n log n) avg, O(n^2) worst, In-place (O(log n) stack), NOT stable.
  8. Heap Sort = O(n log n) worst, In-place (O(1)), NOT stable.
  9. Radix Sort requires a stable digit-by-digit sub-sort (usually Counting Sort) to preserve prior digit order.
  10. Strassen's Matrix Multiplication uses 7 multiplications → O(n^2.81).
  11. Activity Selection sorts greedily by earliest finish time.
  12. Fractional Knapsack is Greedy (O(n log n)); 0/1 Knapsack is DP (O(nW) pseudo-polynomial).
  13. Huffman Coding builds an optimal prefix-free binary tree in O(n log n) via Min-Heap.
  14. Kruskal's MST uses Disjoint Set Union (O(E log E), sparse graphs); Prim's MST grows one tree (dense graphs).
  15. An MST of a connected graph with V vertices ALWAYS has V - 1 edges; distinct edge weights ⇒ unique MST.
  16. DP requires Optimal Substructure + Overlapping Subproblems.
  17. Matrix Chain Multiplication = O(n^3) time; LCS & Edit Distance = O(mn).
  18. Dijkstra (Greedy, O((V+E) log V)) FAILS on negative edge weights.
  19. Bellman-Ford (DP, O(VE)) handles negative edges and detects negative cycles on the V-th relaxation pass.
  20. Floyd-Warshall (All-Pairs DP, O(V^3)) detects negative cycles via dist[i][i] < 0.
  21. KMP String Matching runs in worst-case O(n + m) with zero text backtracking via the LPS array.
  22. Rabin-Karp uses a rolling hash (avg O(n + m), worst O(nm) due to hash collisions).
  23. Backtracking = DFS + pruning (feasibility); Branch-and-Bound = BFS/Best-First + cost bound (optimization).
  24. NP = verifiable in polynomial time (NOT "non-polynomial"); NP-Complete = NP ∩ NP-Hard.
  25. Cook–Levin Theorem: SAT is the first NP-Complete problem; Halting Problem is NP-Hard but NOT in NP!
