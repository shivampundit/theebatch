B. Pointers, Dynamic Memory & Struct vs. Union Traps

  • Pointer Arithmetic: Adding k to pointer T *p advances address by k × sizeof(T) bytes (e.g., int *p at 1000 → p + 3 = 1012 on 4-byte int).
  • Const Pointer Distinction: const int *p = pointer to constant int (cannot modify *p, can change p); int *const p = constant pointer (can modify *p, cannot change p).
  • malloc vs. calloc: malloc(n * sizeof(int)) allocates uninitialized (garbage) memory; calloc(n, sizeof(int)) zero-initializes every byte.
  • Dangling vs. Wild Pointer vs. Memory Leak: Wild Pointer = uninitialized pointer (random address); Dangling Pointer = points to memory already freed via free(p) (fix: set p = NULL); Memory Leak = heap memory allocated with no remaining pointer referencing it.
  • Struct vs. Union: In a struct, each member gets separate memory (total size = sum + alignment padding). In a union, all members share the same memory offset (size = size of largest member, aligned).
  • Macro Trap: #define SQ(x) x*x expands SQ(3+2) to 3+2*3+2 = 11 (NOT 25!) because preprocessor does pure text substitution without parentheses.

4.3 C++ Deep Dive: References, Virtual Dispatch (vtable/vptr), RAII & STL

  • Reference (int &r = x) vs. Pointer: A C++ reference must be initialized at declaration, cannot be NULL, and cannot be reseated to another variable.
  • new/delete vs. malloc/free: new is an operator that allocates memory AND invokes the Constructor (type-safe, throws std::bad_alloc); malloc is a C library function returning void* (returns NULL on failure, no constructor).
  • Runtime Polymorphism (vtable & vptr): When a class declares at least one virtual function, the compiler creates one per-class vtable (Virtual Method Table) of function pointers and embeds a hidden vptr inside every object instance (adding 4 or 8 bytes to sizeof(obj)!).
  • Virtual Destructor Rule: Always declare the base-class destructor virtual when deleting derived objects via a base pointer (Base *b = new Derived(); delete b;)—otherwise the derived destructor never runs (memory/resource leak).
  • Pure Virtual Function & Abstract Class: virtual void pay() = 0; makes the class abstract (cannot be instantiated directly).
  • Diamond Problem: Solved using Virtual Inheritance (class B : virtual public A) so the bottom derived class inherits only ONE shared sub-object of A.
  • Smart Pointers (RAII — C++11+): std::unique_ptr (exclusive ownership, zero overhead, move-only), std::shared_ptr (reference-counted shared ownership), std::weak_ptr (non-owning observer that breaks circular shared_ptr reference cycles).
  • STL Time Complexities: std::vector (O(1) random access, amortized O(1) push_back), std::map / std::set (Red-Black Tree: O(log n)), std::unordered_map (Hash Table: O(1) avg, O(n) worst).

4.5 Python Deep Dive: Mutability, LEGB Scope, Generators & GIL

Modern Paper III Favorite
  • Mutable vs. Immutable: • Immutable (hashable → usable as dict keys / set elements): int, float, bool, str, tuple, frozenset, bytes.
    • Mutable (unhashable): list, dict, set, bytearray. (Trap: a tuple containing a list is NOT hashable!)
  • is vs. ==: == checks value equality; is checks object identity (id(a) == id(b)). CPython caches small integers [-5, 256], so a=256; b=256; a is b is True, whereas larger ints may be False.
  • Shallow vs. Deep Copy: b = a creates an alias (same object). b = a.copy() or a[:] creates a Shallow Copy (new outer list, but inner nested lists are STILL shared!). copy.deepcopy(a) recursively copies nested structures.
  • LEGB Scope Resolution Order: Local → Enclosing (closure) → Global → Built-in. Use global to rebind module-level variables and nonlocal to rebind enclosing-function variables.
  • Generators (yield) vs. List Comprehensions: [x*x for x in range(10**7)] allocates the full list in RAM (O(n) space); (x*x for x in range(10**7)) is a lazy Generator yielding 1 item at a time in O(1) memory.
  • Global Interpreter Lock (GIL): In CPython, the GIL allows only ONE thread to execute Python bytecode at a time to protect reference counts. Thus, for CPU-bound ML/analytics use multiprocessing (or C-extension NumPy/Pandas which release the GIL); for I/O-bound API calls use threading or asyncio.

4.6 Worked Code-Output & Tracing Lab (8 Classic Paper III Traps)

Step-by-Step Output Analysis
Trace 1 (C — Static Variable + Recursion) 
int fun(int n) {
  static int x = 0;
  if (n > 0) { x++; return fun(n - 1) + x; }
  return 0;
}
// Output of printf("%d", fun(4));
Trace: x is static (single shared copy!). All 4 recursive calls execute x++ BEFORE unwinding, so x reaches 4. During unwinding, each frame adds the CURRENT value of x (= 4): 0 + 4 + 4 + 4 + 4 = 16 (NOT 1+2+3+4=10!).
Trace 2 (C — Short-Circuit Evaluation Trap) 
int a = 0, b = 5, c = 10;
int r = (a && ++b) || (c-- > 9);
// Values of r, b, c?
Trace: In (a && ++b), since a == 0 (false), ++b is SHORT-CIRCUITED (never executed!), so b stays 5. Next, || evaluates (c-- > 9): post-decrement compares 10 > 9 (true → r = 1), then decrements c to 9. Result: r=1, b=5, c=9.
Trace 3 (C++ — Virtual vs. Non-Virtual Dispatch) 
class Base {
public:
  void show() { cout << "B1 "; }
  virtual void print() { cout << "B2"; }
};
class Derived : public Base {
public:
  void show() { cout << "D1 "; }
  void print() override { cout << "D2"; }
};
Base *ptr = new Derived();
ptr->show(); ptr->print();
Trace: show() is non-virtual → static binding (pointer type Base*) prints B1. print() is virtual → dynamic binding via vptr (actual object Derived) prints D2. Output: B1 D2.
Trace 4 (C++ — Constructor & Destructor Execution Order) Rule: When creating a Derived object, constructors execute Top-Down (Base → Derived), while destructors execute strictly in reverse Bottom-Up (Derived → Base).
Trace 5 (Java — String Constant Pool Trap) 
String s1 = "SIDBI";
String s2 = "SIDBI";
String s3 = new String("SIDBI");
System.out.println((s1 == s2) + " " + (s1 == s3) + " " + s1.equals(s3));
Trace: s1 and s2 share the exact same String Pool reference (true). new String() forces a distinct Heap object, so s1 == s3 is false, while content check s1.equals(s3) is true. Output: true false true.
Trace 6 (Java — try / catch / finally Return Precedence) 
static int test() {
  try { return 10; }
  finally { return 20; }
}
Trace: A finally block ALWAYS executes before the method returns; a return inside finally overrides the try return value! Output: 20.
Trace 7 (Python — Mutable Default Argument Trap!) 
def add_loan(id, items=[]):
  items.append(id)
  return items
print(add_loan(101), add_loan(102))
Trace: Default arguments in Python are evaluated ONCE at function definition time, not per call! Both calls mutate the SAME list object. Output: [101] [101, 102] (Fix: use items=None).
Trace 8 (Python — Shallow Copy Nested Mutation) 
a = [[1, 2], [3, 4]]
b = a[:]          # shallow copy
b[0].append(99)
print(a[0])
Trace: Slicing a[:] creates a shallow copy—outer list is new, but b[0] and a[0] still reference the SAME inner list! Output: [1, 2, 99].

4.8 5-Minute Rapid Revision Sheet (25 High-Yield One-Liners)

Last-Day Cram
  1. C memory layout (low → high): Text → .data (init) → .bss (uninit=0) → Heap (↑) → Stack (↓).
  2. static local variable lives in .data/.bss, defaults to 0, and retains value across function calls.
  3. static global variable enforces internal linkage (file-private).
  4. calloc(n, sz) zero-initializes memory; malloc(n*sz) leaves garbage bytes.
  5. Cannot take address (&) of a register variable in C.
  6. const int *p = pointer to constant data; int *const p = constant pointer.
  7. union size = largest member (shared memory); struct size = sum of members + alignment padding.
  8. C && and || use short-circuit evaluation (right operand skipped if result already decided).
  9. C++ references cannot be NULL and cannot be reseated after initialization.
  10. C++ virtual functions use per-class vtable and per-object vptr for runtime dispatch.
  11. Base class with virtual functions should always declare a virtual destructor to prevent leaks.
  12. C++ Diamond Problem is resolved by Virtual Inheritance (virtual public).
  13. std::weak_ptr breaks circular reference cycles created by std::shared_ptr.
  14. Java is STRICTLY Pass-by-Value (copies object reference value, never true pass-by-reference).
  15. Java String is immutable (pooled); StringBuilder = fast/unsafe; StringBuffer = synchronized.
  16. Java == compares object references; .equals() compares content.
  17. finally overrides try return values and executes unless System.exit(0) or JVM crash occurs.
  18. Java Checked Exceptions (IOException, SQLException) must be handled/declared at compile time.
  19. HashMap allows 1 null key; Hashtable and ConcurrentHashMap forbid null keys/values.
  20. Java static methods are hidden (compile-time), NOT overridden (runtime).
  21. Python is Dynamically and Strongly typed (no implicit "5" + 2 coercion).
  22. Python immutable types: int, float, str, tuple, frozenset, bytes; mutable: list, dict, set.
  23. Python default mutable arguments (def f(a=[])) are evaluated once at function definition.
  24. Python scope lookup order = LEGB (Local → Enclosing → Global → Built-in).
  25. CPython GIL serializes CPU threads → use multiprocessing for CPU-bound tasks and asyncio/threading for I/O.
