7.1 Kernel Architectures, System Calls, Process Lifecycle & Threads

Core Foundation
  • Dual-Mode Protection: Hardware Mode Bit separates User Mode (Ring 3, bit=1) from Kernel Mode (Ring 0, bit=0). User apps request privileged I/O or memory ops via a System Call (Software Interrupt / Trap).
  • Kernel Architectures: Monolithic (Linux — all OS services in Ring 0; fastest IPC, single driver bug can crash kernel) vs. Microkernel (QNX/Mach — only IPC, scheduling & basic VM in Ring 0; drivers in user space; safer isolation, higher IPC overhead) vs. Hybrid (Windows NT, macOS XNU).
  • Schedulers: Long-Term (Job) controls Degree of Multiprogramming (New → Ready); Short-Term (CPU) picks next Ready process to Run (ms frequency); Medium-Term (Swapper) suspends/swaps processes to disk to relieve RAM pressure.
  • Unix Process Traps: fork() returns 0 to child and child's PID to parent (calling fork() n times creates 2^n total processes, i.e. 2^n - 1 new children!). Zombie Process: Terminated child whose exit status has not yet been reaped by parent via wait() (occupies PCB slot). Orphan Process: Running child whose parent terminated early (adopted by init/systemd PID 1).

Processes vs. Threads (High-Yield MCQ Distinction)

  • Shared across threads of the same process: Code (Text), Data (.data/.bss), Heap, Open File Descriptors, Signals.
  • Private per thread (TCB): Thread ID, Program Counter (PC), CPU Registers, and Thread Stack.
  • User-Level Threads (ULT) vs. Kernel-Level Threads (KLT): ULT context-switch is ultra-fast (no kernel trap), but one blocking I/O syscall blocks ALL threads in the process (Many-to-One) and cannot exploit multi-core CPUs. KLT (One-to-One — Linux pthreads, Java threads) run truly in parallel across cores.

7.2 CPU Scheduling Algorithms & Metrics

Guaranteed Numerical Topic

Core Formulas: TAT (Turnaround Time) = Completion Time (CT) - Arrival Time (AT) • WT (Waiting Time) = TAT - Burst Time (BT) • RT (Response Time) = First CPU Time - AT.

Algorithm Preemptive? Starvation? Key Properties & Exam Traps
FCFS No No Suffers Convoy Effect (short processes stuck behind one long CPU-bound job).
SJF (Non-Preemptive) No Yes Optimal minimum avg WT among non-preemptive schedulers; future burst predicted via exponential averaging τ_(n+1) = αt_n + (1-α)τ_n.
SRTF (Preemptive SJF) Yes Yes Provably optimal minimum average Waiting Time among ALL scheduling algorithms.
Priority Scheduling Both Yes Starvation solved by Aging (gradually boosting priority of waiting jobs). Priority Inversion solved by Priority Inheritance.
Round Robin (RR) Yes (Quantum q) No Best for time-sharing response time. If q → ∞, degrades to FCFS; if q → 0, excessive context-switching.
MLFQ Yes No (with aging) Multilevel Feedback Queue lets processes move between priority queues based on CPU burst behavior (used in real OSes).

7.3 Process Synchronization, Critical Section, Semaphores & Monitors

  • 3 Mandatory Critical Section Requirements: (1) Mutual Exclusion (at most 1 process in CS), (2) Progress (selection among waiting processes cannot be postponed indefinitely), (3) Bounded Waiting (finite limit on how many times others enter before a waiting process gets its turn).
  • Peterson's Algorithm: Software-only 2-process solution satisfying all 3 requirements using flag[2] and turn.
  • Semaphores (Dijkstra): Atomic wait(S) / P(S) decrements S (blocks if S ≤ 0); signal(S) / V(S) increments S (wakes a blocked process). • Counting Semaphore controls access to k identical resource instances.
    • Mutex vs. Binary Semaphore Trap: A Mutex has strict ownership (only the locking thread can unlock it, supporting priority inheritance), whereas a Binary Semaphore can be signaled by ANY thread (ideal for producer-consumer signaling).
  • Monitors: High-level language synchronization construct (e.g., Java synchronized) encapsulating shared data, mutual exclusion, and condition variables (wait()/notify()).

7.4 Deadlocks: Coffman Conditions, RAG & Banker's Algorithm

Top Paper III Objective Zone
  • 4 Necessary Coffman Conditions (ALL 4 must hold simultaneously): 1. Mutual Exclusion (non-shareable resource), 2. Hold and Wait (holding ≥1 resource while waiting for more), 3. No Preemption (resources released only voluntarily), 4. Circular Wait (P0 → P1 → ... → P0 — broken by imposing total resource ordering!).
  • Resource Allocation Graph (RAG) Rule: • If every resource type has a single instance, a cycle in RAG is BOTH necessary and sufficient for deadlock.
    • If resource types have multiple instances, a cycle is necessary, NOT sufficient!
  • Banker's Algorithm (Deadlock Avoidance — Dijkstra): Computes Need[i] = Max[i] - Allocation[i] and searches for a Safe Sequence (Need[i] ≤ Work) in O(m · n^2) time (m resource types, n processes). Key Trap: Safe State ⇒ Guaranteed No Deadlock, but Unsafe State ≠ Deadlock (it only means deadlock is possible!).
  • Deadlock-Free Resource Minimum Formula: For n processes each needing at most k instances of a resource, minimum instances guaranteeing NO deadlock = n(k - 1) + 1.

7.5 Memory Management: Paging, Segmentation, TLB & Virtual Memory

Highest Numerical Yield in OS
Scheme Division Unit Fragmentation Hardware & Key Exam Fact
Contiguous Dynamic Variable partitions External Fragmentation First-Fit, Best-Fit, Worst-Fit; fixed via Compaction.
Paging Fixed-size Pages = Frames Internal Fragmentation (avg 0.5 page/process; ZERO external!) Logical Addr = (p, d); Page Table maps p → f; offset d unchanged!
Segmentation Variable logical units (Code, Stack, Heap) External Fragmentation Segment Table stores (Base, Limit); checks offset < Limit else Trap!
Inverted Page Table 1 entry per Physical Frame Internal One global table for entire OS (saves RAM on 64-bit CPUs); uses hashing to speed lookup.
  • TLB Effective Access Time (EAT): EAT = h(T_tlb + T_mem) + (1 - h)(T_tlb + 2 · T_mem) (single-level page table; for L-level page table, miss adds (L + 1) · T_mem!).
  • Page Replacement Algorithms: • FIFO: Simple queue, suffers Belady's Anomaly (increasing frames can INCREASE page faults!).
    • Optimal (MIN): Replaces page unused for longest future time (impossible online, lowest faults, no Belady).
    • LRU (Least Recently Used): Stack algorithm, NO Belady's Anomaly, high hardware overhead.
    • Clock (Second-Chance): Circular buffer using 1 Reference Bit (practical Linux/OS approximation of LRU).
  • Demand Paging EAT & Thrashing: EAT = (1 - p) · ma + p · S (p = page fault rate, S = page fault service time). Thrashing occurs when degree of multiprogramming exceeds available frames so processes spend more time paging than executing → CPU utilization plummets. Controlled via Working-Set Model (Denning) and Page Fault Frequency (PFF).

7.6 File Allocation (Unix Inodes) & Disk Scheduling

  • File Allocation: Contiguous (fastest sequential/direct read, external fragmentation, hard to grow), Linked / FAT (no external frag, poor random access O(n)), Indexed / Unix Inode (stores metadata + 12 direct pointers + 1 single indirect + 1 double indirect + 1 triple indirect → fast small files AND huge multi-TB files!).
  • Disk Access Time: Seek Time (arm to track) + Rotational Latency (avg = 1/2 revolution) + Transfer Time.
  • Disk Scheduling Comparison: FCFS (fair, high seek), SSTF (Shortest Seek Time First — greedy, can cause starvation), SCAN (Elevator) (sweeps to track 0 or max and reverses), C-SCAN (sweeps one direction to end, jumps back without servicing → uniform wait time), LOOK / C-LOOK (reverses/jumps at the last pending request instead of wasting travel to empty disk boundary!).

7.7 Worked Exam Numericals (8 Step-by-Step OS Problems)

Guaranteed 2-Mark Scoring Zone
Numerical 1: SRTF (Preemptive SJF) Avg Waiting & Turnaround Time Processes: P1(AT=0, BT=8), P2(AT=1, BT=4), P3(AT=2, BT=9), P4(AT=3, BT=5).
Gantt: 0–1: P1(rem 7) → 1–5: P2(done, CT=5) → 5–10: P4(done, CT=10) → 10–17: P1(done, CT=17) → 17–26: P3(done, CT=26).
TAT = CT - AT: P1=17, P2=4, P3=24, P4=7 (Avg TAT = 52/4 = 13.0).
WT = TAT - BT: P1=9, P2=0, P3=15, P4=2 (Avg WT = 26/4 = 6.5).
Numerical 2: Round Robin (Quantum q = 3) Processes (all AT=0): P1(BT=5), P2(BT=4), P3(BT=2).
Gantt: 0–3: P1(rem 2) → 3–6: P2(rem 1) → 6–8: P3(CT=8) → 8–10: P1(CT=10) → 10–11: P2(CT=11).
WT: P1=5, P2=7, P3=6 → Avg WT = 18/3 = 6.0.
Numerical 3: Deadlock-Free Minimum Resource Instances Problem: 5 processes each require at most 4 tape drives to complete. What is the minimum number of tape drives guaranteeing ZERO deadlock?
Formula: n(k - 1) + 1 = 5(4 - 1) + 1 = 15 + 1 = 16 drives.
Numerical 4: Paging Address Split & Page Table Size Problem: 32-bit Logical Address, 4 KB Page Size, 4-byte Page Table Entry (PTE). Find page bits, offset bits, and single-level Page Table size.
Solution: Page Size = 4 KB = 2^12 B → Offset = 12 bits; Page Number = 32 - 12 = 20 bits.
Number of entries = 2^20 (1M entries). Page Table Size = 2^20 × 4 B = 4 MB per process!
Numerical 5: TLB Effective Access Time (EAT) Problem: TLB hit ratio h = 80%, TLB lookup = 20 ns, RAM access = 100 ns.
Solution: EAT = 0.80(20 + 100) + 0.20(20 + 200) = 96 + 44 = 140 ns.
Numerical 6: Page Replacement Faults (FIFO vs. LRU vs. Optimal, 3 Frames) Reference String: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2 (13 refs, 3 frames).
• FIFO: 10 page faults. • LRU: 9 page faults. • Optimal: 7 page faults.
Numerical 7: Unix Inode Max File Size (Direct + Single Indirect) Problem: Block size 4 KB, block pointer 4 B, 12 direct + 1 single-indirect pointer.
Pointers per block: 4096 / 4 = 1024 pointers.
Max blocks: 12 + 1024 = 1036 blocks → Max Size = 1036 × 4 KB = 4,144 KB (≈ 4.05 MB). (Adding 1 double-indirect adds 1024^2 × 4 KB = 4 GB!).
Numerical 8: Disk Scheduling Head Movement (SCAN vs. C-LOOK) Queue: [98, 183, 37, 122, 14, 124, 65, 67], Cylinders 0–199, Start Head = 53 moving toward 199.
• SCAN (hits 199): 53 → 199 (146) + 199 → 14 (185) = 331 cylinders.
• C-LOOK (stops at 183, jumps to 14): (183 - 53) + (183 - 14) + (37 - 14) = 130 + 169 + 23 = 322 cylinders.

  4. Zombie = exited child waiting for parent's wait(); Orphan = live child adopted by PID 1.
  5. Threads share Code, Data, Heap & Files; each thread has its own Stack, Registers & PC.

  7. Priority Scheduling starvation is fixed by Aging; Priority Inversion is fixed by Priority Inheritance.
  8. Round Robin with q → ∞ behaves identically to FCFS.
  9. Critical Section requires: Mutual Exclusion, Progress, and Bounded Waiting.
  10. Mutex has strict thread ownership; Binary Semaphore does not.
  11. 4 Coffman Conditions: Mutual Exclusion, Hold & Wait, No Preemption, Circular Wait.
  12. RAG cycle = necessary & sufficient for single-instance resources; necessary ONLY for multi-instance.
  13. Banker's Algorithm (O(m·n^2)): Safe ⇒ No Deadlock; Unsafe ≠ Deadlock.
  14. Min deadlock-free instances for n processes each needing max k = n(k - 1) + 1.
  15. Paging causes Internal Fragmentation (zero external); Segmentation causes External Fragmentation.
  16. Inverted Page Table has 1 entry per physical RAM frame (1 global table for entire OS).
  17. TLB EAT = h(T_tlb + T_mem) + (1 - h)(T_tlb + 2·T_mem).
  18. FIFO suffers Belady's Anomaly; LRU & Optimal (stack algorithms) NEVER suffer Belady's Anomaly.
  19. Demand Paging EAT = (1 - p)·ma + p·S.

  21. Unix Inode uses Direct + Single/Double/Triple Indirect pointers for fast random access & huge files.
  22. SSTF disk scheduling can cause starvation of distant cylinders.
  23. SCAN travels to disk boundary; LOOK reverses at the last pending request.
  24. C-SCAN / C-LOOK provide more uniform wait times than SCAN/LOOK.
  25. Linux HugePages shrink Page Tables and reduce TLB misses on large Core Banking DB servers.
