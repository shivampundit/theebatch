11.1 Security Foundations: CIA Triad, Access Control Models & Zero Trust

Core Foundation
  • CIA Triad + Extensions: Confidentiality (prevent unauthorized disclosure → Encryption, RBAC), Integrity (prevent unauthorized modification → Hashing, HMAC, Digital Signatures), Availability (timely reliable access → Redundancy, DDoS protection, DR), Non-Repudiation (sender cannot deny sending → Digital Signatures with sender's private key).
  • AAA & MFA: Authentication (who are you?), Authorization (what can you do?), Accounting (audit trail). MFA requires ≥2 distinct factors: Knowledge (password/PIN), Possession (FIDO2/hardware token/OTP), Inherence (biometrics).
  • Access Control Models (High-Yield Exam Traps!): • DAC (Discretionary): Resource owner sets permissions (e.g., Linux chmod).
    • MAC (Mandatory): OS/Admin enforces security labels (SELinux).
    • Bell-LaPadula Model (Confidentiality): No Read Up (Simple Security) & No Write Down (*-Property).
    • Biba Model (Integrity): No Read Down & No Write Up (exact inverse of Bell-LaPadula!).
    • RBAC (role-based) & ABAC (attribute/context-based: role + device posture + geo + time).
  • Zero Trust Architecture (NIST SP 800-207): Replaces implicit perimeter trust ("castle-and-moat") with "Never Trust, Always Verify"—continuous identity/device verification, Least Privilege, Assume Breach, and East-West micro-segmentation.

11.2 Cryptography Mastery: AES, RSA, ECC, Hashing, PKI & Digital Signatures

Top Paper III Objective Zone
Primitive Algorithms & Key/Output Sizes Core Properties & Exam Traps
Symmetric (Secret-Key) AES (128/192/256-bit key; 10/12/14 rounds; 128-bit block), ChaCha20.
Broken/Deprecated: DES (56-bit), 3DES, RC4.		 Very fast (bulk data encryption). AES-GCM provides AEAD (Encryption + Auth). ECB mode is insecure (identical plaintext blocks → identical ciphertext blocks!).
Asymmetric (Public-Key) RSA (2048/4096-bit), ECC (256-bit ≈ 3072-bit RSA!), Diffie-Hellman (ECDHE). Solves key distribution (2n keys vs. n(n-1)/2 symmetric keys). Slow → used for handshakes & signatures. Encrypt with Receiver's Public Key (Confidentiality); Sign with Sender's Private Key (Non-Repudiation).
Hashing & MAC SHA-256 (256-bit), SHA-3 (Keccak), HMAC.
Broken: MD5 (128-bit), SHA-1 (160-bit).		 One-way, deterministic, Avalanche Effect, Collision-Resistant. Passwords MUST use salted slow KDFs: Argon2id, bcrypt, or PBKDF2 (NEVER raw SHA-256!).
PKI & Post-Quantum X.509 Certificates, CA, RA, CRL, OCSP (real-time revocation), NIST PQC (ML-KEM / ML-DSA). Digital Certificate binds an entity's identity to its Public Key, signed by a trusted Certificate Authority (CA).

11.3 Network & Transport Security: TLS 1.3, IPsec, Firewalls, IDS/IPS & Kerberos

  • TLS 1.3 (RFC 8446): Cuts handshake latency to 1-RTT (vs. 2-RTT in TLS 1.2), mandates Perfect Forward Secrecy (ECDHE) so past recorded traffic stays safe even if server private key leaks later, and strips legacy weak ciphers (RSA key transport, CBC, SHA-1, RC4).
  • IPsec (Layer-3 VPN Security): • AH (Authentication Header): Integrity + Auth ONLY (NO encryption).
    • ESP (Encapsulating Security Payload): Confidentiality (Encryption) + Integrity + Auth.
    • Transport Mode (host-to-host; encrypts payload only) vs. Tunnel Mode (site-to-site VPN; encrypts entire original IP packet including original IP header!).
  • Firewalls & IDS/IPS: Stateless Packet Filter (L3/L4 ACLs) → Stateful Firewall (tracks TCP session state) → WAF (L7 HTTP/SQLi/XSS protection) → NGFW (DPI + IPS + App-ID). IDS = passive monitoring/alerting (out-of-band SPAN/TAP); IPS = inline active blocking.
  • Kerberos (Active Directory SSO): Uses a central KDC (Authentication Server AS + Ticket Granting Server TGS) issuing time-stamped symmetric tickets (TGT → Service Ticket) over UDP/TCP port 88—never sends plaintext passwords over the network!

11.5 SOC Operations: SIEM, SOAR, EDR/XDR, MITRE ATT&CK & Incident Response

  • Modern SOC Stack: SIEM (collects, normalizes & correlates logs across firewalls/AD/CBS to fire alerts), SOAR (automates repetitive enrichment & containment playbooks—cutting MTTR), EDR / XDR (deep endpoint/cross-domain behavioral telemetry & host isolation), UEBA (ML baseline detecting compromised insider credentials).
  • MITRE ATT&CK Framework: Global knowledge base of adversary Tactics (Why — 14 tactics: Reconnaissance → Initial Access → Execution → Persistence → Privilege Escalation → Defense Evasion → Credential Access → Discovery → Lateral Movement → Collection → C2 → Exfiltration → Impact) and Techniques (How).
  • NIST Incident Response Lifecycle (4 Phases): 1. Preparation → 2. Detection & Analysis → 3. Containment, Eradication & Recovery → 4. Post-Incident Activity.
  • VAPT & Teams: VA (automated broad scanning to list known CVEs) vs. PT (active exploitation to prove business impact). Red Team (offensive adversary emulation), Blue Team (SOC defenders), Purple Team (collaborative detection tuning).

11.7 Worked Crypto & InfoSec Risk Numericals (6 Problems)

2-Mark Paper III Drills
Numerical 1: Complete RSA Key Generation & Encryption Given: Primes p = 5, q = 11, public exponent e = 3, plaintext M = 7.
Step 1: n = p × q = 55; Euler's Totient φ(n) = (p-1)(q-1) = 4 × 10 = 40.
Step 2 (Private Key d): Find d such that (e · d) mod 40 = 1 ⇒ 3 × 27 = 81 ≡ 1 (mod 40) → d = 27.
Step 3 (Encrypt): C = M^e mod n = 7^3 mod 55 = 343 mod 55 = 13.
Numerical 2: Diffie-Hellman Shared Secret Key Exchange Given: Prime p = 23, generator g = 5, Alice secret a = 6, Bob secret b = 15.
• Alice sends A = 5^6 mod 23 = 15625 mod 23 = 8.
• Bob sends B = 5^15 mod 23 = 19.
• Shared Key K = B^a mod 23 = 19^6 mod 23 = 2 (identical to A^b mod 23 = 8^15 mod 23 = 2!).
Numerical 3: Symmetric vs. Asymmetric Key Scaling Problem: 100 partner banks/NBFCs need secure pairwise encrypted channels on a lending network.
• Symmetric Keys Needed: n(n - 1) / 2 = 100 × 99 / 2 = 4,950 keys.
• Asymmetric Keys Needed: 2n = 200 keys (100 public + 100 private).
Numerical 4: Quantitative Risk Analysis (SLE & ALE) Given: Core Lending Server Asset Value AV = ₹2,00,00,000 (2 Cr), Exposure Factor EF = 25% (0.25), Annualized Rate of Occurrence ARO = 0.5 (once every 2 years).
• Single Loss Expectancy (SLE = AV × EF): 2 Cr × 0.25 = ₹50 Lakh.
• Annualized Loss Expectancy (ALE = SLE × ARO): 50 L × 0.5 = ₹25 Lakh/year (justifies spending up to ₹25L/yr on countermeasure!).
Numerical 5: Bell-LaPadula vs. Biba Access Check User clearance = Secret; File A = Top-Secret; File B = Unclassified.
• Bell-LaPadula (Confidentiality — No Read Up, No Write Down): Can Read File B & Write File A; DENIED Read File A & Write File B.
• Biba (Integrity — No Read Down, No Write Up): Can Read File A & Write File B; DENIED Read File B & Write File A.
Numerical 6: Birthday Paradox Hash Collision Bound For a cryptographic hash of n bits, brute-force pre-image takes 2^n ops, whereas finding ANY collision via the Birthday Attack takes only 2^(n / 2) ops (e.g., SHA-256 collision strength = 2^128 ops).

11.9 5-Minute Rapid Revision Sheet & 15 Exam-Level Practice MCQs

Last-Day Cram + Drill
  1. Bell-LaPadula = Confidentiality (No Read Up, No Write Down); Biba = Integrity (No Read Down, No Write Up).
  2. Zero Trust (NIST SP 800-207): Never trust, always verify; assume breach; least privilege.
  3. AES = 128-bit block; 128/192/256-bit keys (10/12/14 rounds); AES-GCM = AEAD; ECB leaks patterns.
  4. RSA relies on integer factorization; ECC-256 equals RSA-3072 security at much smaller key size.
  5. Symmetric pairwise keys for n users = n(n-1)/2; Asymmetric = 2n.
  6. Digital Signature signs hash with Sender's Private Key → provides Integrity, Auth & Non-Repudiation (NOT confidentiality!).
  7. MD5 (128-bit) & SHA-1 (160-bit) are cryptographically broken; use SHA-256 / SHA-3.
  8. Store passwords using salted slow KDFs: Argon2id, bcrypt, or PBKDF2.
  9. Birthday collision resistance for an n-bit hash is 2^(n/2).
  10. OCSP checks real-time X.509 certificate revocation (faster than downloading full CRLs).
  11. TLS 1.3 = 1-RTT handshake + mandatory Perfect Forward Secrecy (ECDHE).
  12. IPsec AH = Auth/Integrity only (no encryption); IPsec ESP Tunnel Mode encrypts entire original IP packet for VPNs.
  13. IDS alerts passively; IPS sits inline and actively blocks traffic.
  14. Kerberos (port 88) uses KDC (AS + TGS) with symmetric time-stamped tickets (TGT).
  15. OWASP Top 10:2025: A01 Broken Access Control (absorbs SSRF), A02 Security Misconfiguration, A03 Software Supply Chain Failures, A10 Mishandling of Exceptional Conditions.
  16. Fix SQL Injection with Parameterized Queries / Prepared Statements.
  17. Fix XSS with Output Encoding + CSP + HttpOnly; fix CSRF with Anti-CSRF token + SameSite cookie.
  18. Mitigate SYN Flood DDoS using SYN Cookies.
  19. SIEM = log correlation & alerts; SOAR = automated orchestration & response playbooks.
  20. NIST IR Lifecycle: Preparation → Detection & Analysis → Containment/Eradication/Recovery → Post-Incident.
  21. Risk math: SLE = AV × EF; ALE = SLE × ARO.
  22. CERT-In Directions (Sec 70B(6)): 6-hour reporting, 180-day rolling logs in India, NIC/NPL NTP sync.
  23. DPDP Rules 2025 (Nov 2025) operationalize DPDP Act 2023 (Data Principal rights, itemized consent, DPB breach notice).
  24. RBI AIFI Cybersecurity & Tech Risk Directions 2026 directly govern SIDBI, NABARD, EXIM, NHB & NaBFID.
  25. ISO/IEC 27001:2022 organizes Annex A into 93 controls across 4 themes.
